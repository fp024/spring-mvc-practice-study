# DOM 이벤트 전파: 버블링(Bubbling)과 캡처링(Capturing)

## 1. 개요
`addEventListener()` 함수의 세 번째 매개변수는 **이벤트 캡처링 사용 여부(`useCapture`)**를 나타냅니다.

```javascript
element.addEventListener(
  "click",
  () => {
    // 이벤트 핸들러 로직
  },
  false // useCapture (기본값: false)
);
```

- 현대 브라우저에서는 기본값이 `false`이므로 생략해도 무방합니다.
- 레거시 브라우저 호환성 또는 버블링 동작을 명시하기 위해 `false`를 명시적으로 작성하기도 합니다.

---

## 2. DOM 이벤트 전파의 3단계
사용자가 요소를 클릭했을 때 브라우저는 다음과 같은 순서로 이벤트를 전파합니다.

```
[window]
   │    ▲
   │    │
 1. 캡처링 (위 → 아래)
   │    │ 3. 버블링 (아래 → 위)
   ▼    │
[부모 요소]
   │    ▲
   ▼    │
[타깃 버튼] ── 2. 타깃 단계
```

1. **캡처링 단계 (Capturing Phase)**: 최상위 `window` / `document`에서 시작하여 실제 클릭된 타깃 요소까지 내려가는 단계
2. **타깃 단계 (Target Phase)**: 이벤트가 실제 클릭된 요소(Target)에 도달하는 단계
3. **버블링 단계 (Bubbling Phase)**: 이벤트가 클릭된 요소로부터 다시 최상위 요소까지 거품처럼 올라가는 단계

---

## 3. `false` (버블링) vs `true` (캡처링)

| 구분 | 옵션 값 | 감지 시점 | 전파 방향 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| **버블링** | `false` | 버블링 단계 | 하위(타깃) → 상위(부모) | 기본값, 표준적인 방식 |
| **캡처링** | `true` | 캡처링 단계 | 상위(부모) → 하위(타깃) | 이벤트를 상위에서 가로챌 때 사용 |

- **클릭된 요소 자체에만 리스너가 걸린 경우**: `true`나 `false` 상관없이 타깃 단계에서 정상 실행됩니다.
- **부모 요소에도 이벤트 리스너가 걸린 경우**: 실행 순서에 차이가 발생합니다.

---

## 4. 부모 요소에 이벤트가 걸려 있을 때의 동작 차이

### 4.1. `false` (버블링, 기본 흐름)
- **실행 순서**: **[버튼 리스너]** → **[부모 리스너]**
- 사용자가 버튼을 클릭하면 버튼의 동작이 먼저 처리되고, 상위 요소로 올라가면서 부모 리스너가 실행됩니다.

### 4.2. `true` (캡처링) 설정 시 주의점
부모 요소에 `useCapture: true`를 적용할 경우 다음과 같은 문제가 발생할 수 있습니다.

1. **실행 순서 왜곡**:
   - 이벤트가 버튼으로 내려가는 도중 부모 리스너가 먼저 낚아채어 실행됩니다 (**[부모 리스너]** → **[버튼 리스너]**).
2. **이벤트 가로채기(먹통 현상)**:
   - 만약 부모 리스너 내부에서 `e.stopPropagation()`(전파 중단)을 호출하면, 이벤트가 자식 요소로 내려가지 못해 **버튼 클릭 핸들러가 아예 실행되지 않습니다.**

---

## 5. 결론 및 권장사항
- 일반적인 웹 UI 개발에서는 자연스러운 사용자 인터랙션 흐름에 맞는 **버블링(`false`, 또는 인자 생략)**을 사용합니다.
- `true`(캡처링)는 특정 영역의 클릭 이벤트를 자식 요소에 도달하기 전 상위에서 강제로 사전 차단하거나 전역 로깅/분석이 필요한 특수한 경우가 아니면 거의 사용하지 않습니다.
